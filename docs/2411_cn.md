## 2. 参考数据约定

### 2.1 输入文件

| 文件 | 形状或格式 | 用途 |
|---|---|---|
| `data{station_id}.npy` | `(4384, 52, 31)` | NWP 因子，唯一模型特征来源 |
| `sta/{station_id}.csv` | 逐小时 CSV | 实况标签来源 |
| `sta/2024/{station_id}.csv` | 逐小时 CSV | 2024 年补充，与根目录按时间去重 |
| `label{station_id}.npy` | 逐站数组 | **弃用**，不是独立观测 |

真实路径由本机 YAML 覆盖文件管理，不要写死在脚本中。

### 2.2 时间轴

| 项 | 参考值 |
|---|---|
| 首个起报 | 2019-01-01 00 UTC |
| 起报间隔 | 12 h |
| 样本数 | 4384，末期为 2024-12-31 12 UTC |
| 原始前段 | 3、6、…、72 h，共 24 个时效 |
| 原始后段 | 78、84、…、240 h，共 28 个时效 |
| 主实验目标 | 13–36 h，逐小时，共 24 个时次 |
| 扩展目标 | 3–240 h，3 h 间隔，共 80 个时次 |

每年起报数由时间轴推导，闰年为 732，其他年份为 730；不能按固定 730
切分年份。

### 2.3 因子列布局

| 索引 | 含义 | 单位 |
|---|---|---|
| 0 / 1 / 2 | 2T / MSL / 2D | K / Pa / K |
| 3 / 4 | 10U / 10V | m/s |
| 5 | 时段累计降水 | m |
| 6–9 | T：1000 / 925 / 850 / 700 hPa | K |
| 10 | T_500 | 全 NaN，丢弃 |
| 11–14 | GH：1000 / 925 / 850 / 700 hPa | gpm |
| 15 | GH_500 | 全 NaN，丢弃 |
| 16–19 | RH：1000 / 925 / 850 / 700 hPa | % |
| 20 | RH_500 | 全 NaN，丢弃 |
| 21–24 | U：1000 / 925 / 850 / 700 hPa | m/s |
| 25 | U_500 | 全 NaN，丢弃 |
| 26–29 | V：1000 / 925 / 850 / 700 hPa | m/s |
| 30 | V_500 | 全 NaN，丢弃 |

最终使用 26 个因子：5 个地面要素、1 个降水、4 层 × 5 个高空要素。
3 h 与 6 h 累计降水先转换为 mm/h，再进行时效插值。其他数据集若列布局
不同，需要调整适配器，不能直接套用这些索引。

### 2.4 为什么弃用 `label{station_id}.npy`

对 57687、58238 两站核验发现，该数组与 NWP 的 10V 高度接近，而不是
独立站点观测。使用它训练会变成“模式拟合模式”。训练和检验必须使用
逐小时站点 CSV 清洗、对齐后的观测。

## 3. 观测清洗与站点质控

清洗顺序在 `src/data_2411.py` 中实现：

1. 先识别静风 `999017` 和缺测码，避免静风被普通范围检查提前清除。
2. 风向 `360 → 0`，保留 `[0, 360)`；风速保留 `[0, 1000)`。
3. 按风向、风速的特殊码和成对规则处理缺测。
4. 相邻观测风速突变超过 10 m/s 时剔除该时次风向和风速。
5. 静风标记且风速小于 0.3 m/s 的样本恢复 `999017` 标记。
6. 降水缺测码转为 NaN；NWP 累计降水另按时效长度转换为 mm/h。
7. 根目录与 2024 子目录按 UTC 时间戳去重。

观测索引必须使用 UTC。QC 可直接读取原始观测，也可复用已有缓存：

```bash
python -m wind10m --config config/datasets/2411.yaml qc
```

参考运行剔除观测缺测率大于 30% 的 46 站，保留 2187 站，输出：

- `docs/results/qc/station_qc.csv`
- `docs/results/qc/stations_ok.txt`
- `docs/results/qc/stations_dropped.txt`

## 4. 缓存与容量预估

| `cache.mode` | 保存内容 | 参考大小 | 用途 |
|---|---|---:|---|
| `none` | 不写文件 | 0 | 默认；内存中按需预处理 |
| `obs` | `dir/spd/pre` | 2.63 GiB | 节省空间，特征按需重算 |
| `full` | `x/dir/spd/pre` | 25.38 GiB | 反复实验、统一和分时效方案 |

参考大小对应 2233 站、4384 样本、24 时次、26 因子。`y/uv` 在加载时由
`dir/spd` 无损重建，旧版完整缓存仍可读取。

```bash
# 参考主实验
python -m wind10m --config config/datasets/2411.yaml \
  estimate-cache --stations 2233 --hours 24

# 设置 cache.mode 为 obs 或 full 后执行
python -m wind10m --config config/datasets/2411.yaml cache
```

容量结果为 float32 数组载荷估算，不含少量 NPZ 元数据开销。早期全量运行
使用旧格式，2233 站占 29.76 GB、建缓存耗时 5.8 min；新完整格式预计减少
约 14.7%。

## 5. 主实验复现

通用默认值在 `config/base.yaml`，参考数据集参数在
`config/datasets/2411.yaml`。主实验使用 `lead.mode: 24`。

```bash
python -m wind10m --config config/datasets/2411.yaml qc
# 可选：cache.mode 设为 obs 或 full 后执行 cache
python -m wind10m --config config/datasets/2411.yaml train
python -m wind10m --config config/datasets/2411.yaml verify
python -m wind10m --config config/datasets/2411.yaml mi
python -m wind10m --config config/datasets/2411.yaml plot
```

训练执行六折留一年验证，每折输出：

- ECMWF-IFS：直接由 10U/10V 合成；
- PDFM：分位数映射；
- MLR：多元线性回归；
- LightGBM-A：风速、正弦、余弦角度编码；
- LightGBM-B：UV 矢量分解。

训练和检验的 `--limit` 必须一致。小样本结果只用于冒烟，不得与全量
共同样本结果混用。

### 7.1 五模型共同样本

| 模型 | 风速 CC | MAE | RMSE | 偏差 | 风速 OA | kappa | 风向 MAE | RMSE | 风向 OA | kappa |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| ECMWF-IFS | 0.599 | 1.065 | 1.425 | +0.315 | 0.468 | 0.209 | 47.78 | 65.69 | 0.361 | 0.267 |
| PDFM | 0.697 | 0.856 | 1.177 | +0.046 | 0.546 | 0.303 | 46.34 | 64.64 | 0.378 | 0.288 |
| MLR | 0.612 | 0.886 | 1.204 | +0.046 | 0.528 | 0.250 | 42.19 | 60.14 | 0.409 | 0.323 |

### 7.2 A/B 编码对比与数值核验

- 相对 B，A 的风速 MAE、RMSE 分别降低 17.92%、18.21%。
- 风向 MAE/RMSE 差异仅 0.18%/0.68%，分类 OA/kappa 则 B 略高。
- B 风速偏差为 −0.534 m/s，A 为 +0.039 m/s。
- 风速六项及风向 MAE/RMSE 与独立指标实现交叉核验，相对差为 0.0000%。
- 正式表与独立逐站六年复核的风向 MAE/RMSE 最大差为 2.49×10⁻¹³。
- 互信息矩阵为 26×26、严格对称；静风、全 NaN、分级边界等断言已通过。

## 8. 十天逐 3 h 产品

```bash
python -m wind10m --config config/datasets/2411.yaml predict-10day
# 小样本检查
python -m wind10m --config config/datasets/2411.yaml predict-10day --limit 3
```

| 项 | 参考实现 |
|---|---|
| 训练窗口 | 原始 52 个时效（3–240 h）全部参与 |
| 推理窗口 | 80 个 3 h 时效 |
| 时效扩展 | 72 h 后线性内插中间点，不是新增预报信息 |
| 特征 | 26 个，与主实验同源，降水换算为 mm/h |
| 输出 | `artifacts/2411/deploy/{station_id}.npz` |
| 数组 | `dir/dir_b/spd/spd_b` 全部 float32 |
| 参考形状 | `(4384, 80)` |
| 参考空间 | A+B 双模型约 18 GB/2187 站 |

LightGBM-A 固定写 `dir/spd`，B 固定写 `dir_b/spd_b`。断点续跑检查文件
是否包含本次要求的全部模型数组；A-only 文件可在后续补齐 B。某个时次
缺测只丢对应训练行，但推理要求 80 个时次特征齐全，否则输出 NaN，不做
前向填充。

主实验只验证 13–36 h，更晚时效需要独立观测检验。任何 `--limit` 运行都是
冒烟检查，结果不得作为正式产品。

## 9. 四方案对比

```bash
python -m wind10m --config config/datasets/2411.yaml benchmark
```

| 方案 | 定义 |
|---|---|
| 统一 | 所有站、所有时效合并训练 |
| 分时效 | 每个时效一个模型，跨站合并训练 |
| 分站 | 每站一个模型，主实验采用 |
| 分站分时效 | 每站、每时效一个模型 |

四方案使用相同训练年份、检验年份、完整特征掩膜和完整目标掩膜。六折
通过平方误差、计数和混淆矩阵合并，不能简单平均逐折 RMSE。默认
`--subset 0` 为全站；选择方案四时，如显式设置 `--subset`，所有方案共用
相同站点子集。方案只比较 LightGBM-A 的组织方式，不包含额外 MLR 基线。

统一/分时效方案由 `model.stream` 控制预加载或 LightGBM `Sequence` 流式
读取，全量运行建议 `cache.mode: full`。并行预算为
`inner × outer ≈ parallel.n_total`。

输出：

- `table6_by_fold.csv|txt`：逐折指标与用时；
- `table6_schemes.csv|txt`：六折合并指标、站数与总用时；
- `table7_by_lead.csv|txt`：逐折、逐时效指标；
- `table7_overall.csv|txt`：六折合并逐时效指标。

全量表 6/7 尚未生成，不能使用估算值作为实验结论。`--limit`、`--subset`
或不完整 `--years` 均为冒烟检查，其结果应丢弃。

## 10. 观测下载与断点

下载器保持单请求串行，半年切片和站点批次仍由使用者控制：

```bash
python -m wind10m download --national --batch-size 30 \
  /path/to/sta 20160101 20261111
```

也可直接使用 `python download_obs.py ...`。自定义站表用
`--station-info /path/to/stations.csv` 替代 `--national`；站号始终按字符串
读取。输出路径、起止日期为必需参数，不再依赖旧全局配置。

- 每个成功响应按站追加 CSV，并原子更新 `.download_state.json`。
- 默认从匹配状态续跑；改变批次大小不会重复已完成的时间片。
- 空响应和明确错误不删除临时文件，其他站群继续执行。
- 空响应不在当次立即重试；再次执行相同命令可重放未完成请求。
- 明确错误默认最多尝试 2 次，可用 `--max-attempts` 和 `--retry-wait` 调整。
- 站点完成全部时间片后独立定稿；整段无观测时生成只有表头的 CSV。
- 只有显式指定 `--restart` 才清理未完成状态和临时 CSV。
- `download.log` 单文件轮转，最多保留一个备份；成功请求不逐条写文本日志。
- 结束汇总实际完整、无数据、未完成站数，以及本次 `fetch_seconds` 和
  `write_seconds`，用于判断后续是否值得加入单请求在途的读写重叠。

首次真实验证应使用小站表和短时间范围，再单独重放此前的 2021 上半年
空响应请求；不要直接启动十一年全量任务。
